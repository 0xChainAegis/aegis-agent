## 三个人怎么并行

1. **开工前约 15 分钟：**每人报告基线 SHA、任务分支、负责文件、先验证的一个问题。用自己的工作副本，不让三个 Agent 同时切换同一目录的 Git 分支。
2. **第一轮约 60–90 分钟：**各自跑相关基线检查并复现问题。已有测试通过不等于当天任务完成；也不要重复实现已有功能。环境装不起来时先报准确命令与错误，继续独立静态核查。
3. **开发约 2–3 小时：**先完成各文件 P0。可复现缺陷做最小修复，重要但未覆盖的风险补回归用例。跨 API/ABI 的改动先给其他两人书面契约，不能各自发明接口。
4. **开发过半时同步 10 分钟：**只讲实际发现、是否影响别人、缺哪个决定。MIA 报接口复现，purple sun 报响应契约，某齐报合约行为和事件。
5. **收尾前至少 60 分钟：**停止添功能，准备 diff、实际测试结果和 PR 草案。某齐审后端的链上授权/事件假设；purple sun 审前端接口/重试；MIA 审合约测试对应的用户结果与演示文字。代码作者负责解释自己的改动。
6. **最后一次联调：**MIA 作为当天集成协调人，人工选择经评审的任务 PR，串行合到集成分支。合并后由一人跑完整 `npm run check` 和隔离环境的 `npm run test:e2e`。另两人核对到账、审批、拦截证据。失败保留失败记录，定位后再验证受影响项。

- 现有 c3164e6 集成提交如实保留，不改作者、不回填日期、不重写历史来营造逐日记录。
